A message bus for agent memory and policy propagation across tool calls — the load-bearing layer under every orchestrated agent demo.

RUBY AGENTS MESSAGE-BUS
Status

Problem

Agent orchestration keeps re-deriving the same plumbing — capability discovery, context handoff, retries, tracing — inline, per integration, with no shared substrate. Every new tool call means another bespoke wiring job.

Approach

Model the handoff as messages on a typed bus instead of function calls between services. Each agent publishes state changes and capability offers; a thin router matches intents to subscribers and stamps every message with trace and policy metadata on the way through.

Bus.publish(:context, payload, trace_id: trace_id) Bus.subscribe(:context) { |msg| Planner.absorb(msg) }

Policy enforcement and approval gates sit as bus middleware, so they apply once instead of once per integration.

Outcome

Three agents now share one bus in production. Adding a fourth took an afternoon instead of a sprint — the new agent only had to speak the message schema, not learn every other agent's API.
